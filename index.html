1오늘의 흐름

Streamlit, 대체 뭐길래?

보통 웹앱을 만들려면 파이썬(서버) + HTML/CSS(화면) + JavaScript(동작) + Flask/Django 같은 프레임워크까지 배워야 합니다. Streamlit은 이 과정을 통째로 생략하고, 파이썬만으로 프론트엔드까지 자동 생성해줍니다.

HTML 구조 작성 CSS 스타일링 JavaScript 이벤트 처리 Flask/Django 서버 API 연동

최소 4~5개 언어·프레임워크를 동시에 다뤄야 버튼 하나 눌렀을 때 화면이 바뀌는 앱을 만들 수 있어요. 배우는 데만 몇 주가 걸리기도 합니다.

파이썬 코드만 작성

st.button(), st.slider() 처럼 함수를 호출하면 Streamlit이 알아서 HTML·CSS·JS를 만들어 브라우저에 그려줍니다. 여러분은 "어떤 화면을 원하는지"만 파이썬으로 표현하면 됩니다.

설치하고 첫 앱 실행하기

한 번만 설정해두면 그다음부터는 streamlit run 한 줄이면 됩니다. 터미널(명령 프롬프트)을 열고 순서대로 따라와 보세요.

1

가상환경 만들기 (선택이지만 강력 추천)

프로젝트 폴더별로 파이썬 패키지를 깔끔하게 분리해두면 나중에 충돌이 안 생겨요.

terminal
python -m venv .venv
# Windows: .venv\Scripts\activate
# macOS/Linux: source .venv/bin/activate
2

Streamlit 설치

파이썬 패키지 관리자 pip로 한 줄이면 끝입니다.

terminal
pip install streamlit
3

설치 확인 (선택)

공식 데모 앱을 열어 잘 설치됐는지 확인해볼 수 있어요.

terminal
streamlit hello
4

app.py 파일 만들기

아무 폴더에나 app.py라는 파일을 만들고 아래 세 줄을 입력하세요.

app.py
import streamlit as st

st.title("나의 첫 Streamlit 앱")
st.write("안녕하세요! 👋")
5

앱 실행!

터미널에 아래 명령어를 입력하면 브라우저가 자동으로 열립니다.

3

화면에 무언가를 출력해보자

Streamlit의 가장 기본이 되는 함수들입니다. 아코디언을 눌러 각 함수의 쓰임새를 확인해보세요.

st.title() / st.header() / st.subheader() — 제목 넣기
페이지의 큰 제목, 중간 제목, 소제목을 각각 담당합니다. HTML의 <h1>~<h3>와 비슷한 역할이에요.
app.py
st.title("동아리 활동 보고서")
st.header("1. 이번 달 활동")
st.subheader("1-1. Streamlit 스터디")
st.write() — 뭐든지 다 출력하는 만능 함수
문자열, 숫자, 리스트, 딕셔너리, 데이터프레임까지 타입을 알아서 인식해서 예쁘게 그려줍니다. 뭘 써야 할지 모르겠다면 일단 st.write()를 쓰세요.
app.py
st.write("그냥 텍스트도 되고")
st.write(3 + 4)
st.write(["사과", "바나나", "포도"])
st.markdown() — 마크다운 문법으로 꾸미기
**굵게**, *기울임*, 이모지, 심지어 색깔 강조(:red[텍스트])까지 지원합니다.
app.py
st.markdown("**굵은 글씨**와 *기울임체*, 그리고 :red[빨간 강조]까지!")
st.image() / st.video() — 이미지·영상 보여주기
파일 경로나 URL을 넣으면 이미지·영상을 바로 화면에 띄울 수 있습니다.
app.py
st.image("logo.png", caption="우리 동아리 로고")
⚠️ Streamlit은 코드를 위에서 아래로 매번 처음부터 다시 실행해서 화면을 그립니다. 이 특징(rerun 모델)을 이해하는 게 나중에 위젯과 세션 상태를 다룰 때 정말 중요해요. 잠시 뒤에 자세히 살펴봅니다!

레이아웃 잡기

위젯을 아무렇게나 나열하면 화면이 지저분해집니다. 사이드바·컬럼·탭·확장 패널로 구조를 잡아봅시다.

app.py
st.sidebar.title("설정")
name = st.sidebar.text_input("이름")
st.title(f"환영합니다, {name}!")

메뉴, 필터, 옵션처럼 항상 보여야 하지만 메인 콘텐츠는 아닌 요소를 왼쪽 사이드바에 넣습니다. st.sidebar.를 앞에 붙이기만 하면 돼요.

app.py
col1, col2 = st.columns(2)
with col1:
    st.metric("오늘 방문자", "128")
with col2:
    st.metric("좋아요", "45")

화면을 가로로 나눠 나란히 배치합니다. st.columns([2,1])처럼 비율도 지정할 수 있어요. 통계 카드나 사진 갤러리에 자주 씁니다.

app.py
tab1, tab2 = st.tabs(["소개", "활동 내역"])
with tab1:
    st.write("우리 동아리는...")
with tab2:
    st.write("3월: 파이썬 기초...")

한 화면에 여러 콘텐츠를 넣되, 클릭해야만 보이게 하고 싶을 때 씁니다. 지금 이 페이지의 코드 비교 탭도 이 방식이에요!

app.py
with st.expander("채점 기준 보기"):
    st.write("1. 코드 실행 여부 (40점)")
    st.write("2. 인터페이스 완성도 (30점)")

평소엔 접혀 있다가 클릭하면 펼쳐지는 패널입니다. 자세한 설명이나 부가 정보를 숨겨둘 때 유용해요.

데이터와 차트 다루기

Streamlit은 pandas 데이터프레임과 찰떡궁합입니다. 표를 만들고 나면 차트는 함수 하나로 끝나요. 우리 동아리 부원들이 좋아하는 과목을 조사했다고 가정해봅시다.

app.py
import pandas as pd
import streamlit as st

df = pd.DataFrame({
    "과목": ["정보","수학","영어","과학"],
    "득표수": [12, 7, 5, 9]
})

st.dataframe(df)          # 표로 보여주기
st.bar_chart(df, x="과목", y="득표수")  # 막대 그래프
과목득표수
정보12
수학7
영어5
과학9
st.bar_chart() 결과 미리보기 — 막대를 클릭해보세요

막대를 클릭하면 득표수가 표시됩니다.

💡 더 화려한 그래프가 필요하면 st.line_chart(), st.area_chart(), 또는 Plotly/Altair 차트를 st.plotly_chart()로 그대로 넣을 수도 있습니다.

st.session_state — Streamlit의 기억력

아까 "Streamlit은 코드를 매번 처음부터 다시 실행한다"고 했던 것, 기억나나요? 그 말은 즉, 버튼을 누른 횟수 같은 값은 기본적으로 기억되지 않는다는 뜻입니다. 아래 두 카운터를 직접 눌러 차이를 확인해보세요.

❌ session_state 없이

app.py
count = 0
if st.button("클릭"):
    count += 1
st.write(f"카운트: {count}")

카운트: 0 (매번 0으로 리셋돼요!)

✅ session_state 사용

app.py
if "count" not in st.session_state:
    st.session_state.count = 0
if st.button("클릭 ", key="good"):
    st.session_state.count += 1
st.write(f"카운트: {st.session_state.count}")

카운트: 0 (값이 계속 쌓여요!)

💡 st.session_state는 파이썬 딕셔너리처럼 동작하는 "저장 공간"이에요. 게임 점수, 로그인 여부, 이전 입력값처럼 다시 실행돼도 유지되어야 하는 값은 반드시 여기에 저장합니다. 잠시 후 만들 미니 프로젝트의 핵심 개념이니 꼭 기억해두세요!

미니 프로젝트: 숫자 맞추기 게임 🎯

지금까지 배운 위젯, 레이아웃, session_state를 모두 활용해 컴퓨터가 생각한 1~100 사이의 숫자를 맞히는 웹 게임을 만들어봅니다. 아래에서 직접 플레이도 해볼 수 있어요.

🎮 미리 해보기

1~100 사이의 숫자를 입력하고 확인을 눌러보세요.

시도 횟수: 0 / 최고 기록: -

📋 완성 코드 미리보기
app.py
import streamlit as st
import random

st.title("🎯 숫자 맞추기 게임")

# 1) 게임 상태 초기화 (최초 1회만)
if "answer" not in st.session_state:
    st.session_state.answer = random.randint(1, 100)
    st.session_state.tries = 0

guess = st.number_input("1~100 사이 숫자", 1, 100, step=1)

if st.button("확인"):
    st.session_state.tries += 1
    if guess < st.session_state.answer:
        st.warning("⬆️ 더 큰 숫자예요!")
    elif guess > st.session_state.answer:
        st.warning("⬇️ 더 작은 숫자예요!")
    else:
        st.success(f"🎉 정답! {st.session_state.tries}번 만에 맞혔어요!")

st.caption(f"시도 횟수: {st.session_state.tries}")

if st.button("다시 시작"):
    del st.session_state.answer
    st.rerun()
🔍 코드 뜯어보기: 왜 이렇게 짰을까?

① 정답을 왜 session_state에 저장할까요? 정답을 그냥 변수로 두면, 버튼을 누를 때마다 코드가 처음부터 다시 실행되면서 random.randint()가 또 호출돼 정답이 계속 바뀌어버립니다. "answer" not in st.session_state로 "이미 정답이 정해져 있으면 새로 뽑지 않는다"는 조건을 걸어준 거예요.

② 시도 횟수는 왜 필요할까요? 게임에 긴장감을 주고, 나중에 "최소 몇 번 만에 맞혔는지" 같은 랭킹 기능으로 확장할 수 있는 좋은 재료입니다.

③ 확장 아이디어 — 난이도 선택(st.radio로 범위 조절), 힌트 개수 제한(st.sidebar에 남은 힌트 표시), 여러 명의 최고 기록을 st.session_state 리스트에 저장해 리더보드 만들기 등으로 발전시켜보세요.

전 세계에 공개하기: GitHub + Streamlit Community Cloud 배포

내 컴퓨터에서만 돌아가던 앱을 누구나 접속할 수 있는 웹 주소로 만들어봅시다. 배포는 크게 두 단계입니다 — ① 코드를 GitHub에 올리기, ② Streamlit Community Cloud와 그 저장소를 연결하기. 하나씩 따라와 보세요.

1부 · GitHub에 코드 올리기

방법은 두 가지예요. git을 몰라도 웹사이트에서 파일을 드래그해서 올리는 방법과, 터미널에서 git 명령어로 올리는 방법 중 편한 쪽을 골라 따라 하세요. (기능은 완전히 동일합니다!)

1

파일 두 개 준비하기

내 컴퓨터의 프로젝트 폴더에 app.py(우리가 만든 게임 코드)와 requirements.txt 두 파일이 있는지 확인합니다.

requirements.txt
streamlit
pandas
2

GitHub 계정 만들기

github.com/signup에 접속해 이메일·비밀번호·username을 입력하고 이메일 인증을 마칩니다. 이미 계정이 있다면 로그인만 하면 돼요.

3

새 저장소(Repository) 만들기

우측 상단 + 버튼 → New repository를 클릭합니다. Repository name에 이름을 입력하고(예: number-guessing-game), Public을 선택한 뒤 Create repository 버튼을 누릅니다.

💡 "Add a README file"은 체크해도, 안 해도 상관없어요. 지금은 빈 저장소든 README만 있는 저장소든 다음 단계에 문제가 없습니다.
4

파일 업로드하기

저장소 페이지에서 Add file 드롭다운 → Upload files를 클릭합니다. app.py와 requirements.txt 두 파일을 화면에 드래그 앤 드롭하거나 choose your files를 눌러 선택합니다.

5

Commit changes로 저장 완료!

페이지 하단 커밋 메시지 칸에 Add streamlit app 같은 짧은 설명을 적고 Commit changes 버튼(브랜치를 새로 만드는 경우엔 Propose changes)을 누르면 업로드가 끝납니다. 저장소 파일 목록에 두 파일이 보이면 성공이에요.

1

terminal

2

GitHub에 빈 저장소 만들기

github.com에서 New repository로 저장소를 만듭니다. 이번엔 "Add a README file"을 체크하지 마세요 — 로컬 코드와 충돌 없이 깔끔하게 푸시하기 위해서예요.

3

프로젝트 폴더에서 git 초기화

app.py, requirements.txt가 들어있는 폴더로 이동해 초기화합니다.

terminal
cd my-streamlit-app
git init
4

파일 추가 & 커밋

terminal

5

GitHub 저장소와 연결

저장소를 만들면 GitHub가 보여주는 주소를 그대로 붙여넣으면 됩니다(본인의 아이디/저장소명으로 바뀝니다).

terminal
git remote add origin https://github.com/내아이디/number-guessing-game.git
git branch -M main
6

푸시(push)로 업로드!

terminal
git push -u origin main

로그인 창이 뜨면 GitHub 계정으로 인증합니다. 완료되면 저장소 페이지를 새로고침해서 파일이 올라갔는지 확인하세요.

⚠️ requirements.txt 파일 이름을 정확히 맞춰야 해요(오타나 대소문자 실수가 배포 실패의 가장 흔한 원인입니다). 이 파일이 없으면 다음 단계에서 Streamlit이 streamlit, pandas 같은 패키지를 어디서 설치해야 할지 몰라 앱이 켜지지 않아요.

🛠️ 더 알아보기 — GitHub 웹사이트에서 파일 관리하기

코드를 올린 뒤에도 실수한 파일을 고치거나 지울 일이 많습니다. 셋 다 터미널 없이 웹사이트에서 바로 할 수 있어요.

📤 파일 업로드하기
저장소 메인 페이지에서 Add file 드롭다운 → Upload files를 클릭합니다. 파일을 화면에 드래그 앤 드롭하거나 choose your files로 선택한 뒤, 아래 커밋 메시지를 입력하고 Commit changes를 누르면 끝이에요.
✏️ 파일명 바꾸기
바꾸고 싶은 파일을 클릭해 내용 화면으로 들어간 뒤, 우측 상단의 연필 아이콘(Edit)을 클릭합니다. 편집 화면 위쪽의 파일명 칸을 새 이름으로 고치고, 아래 Commit changes를 눌러 저장합니다.
🗑️ 파일 삭제하기
마찬가지로 파일을 클릭해 들어간 뒤, 우측 상단의 ⋯ (케밥 메뉴)를 클릭하고 Delete file을 선택합니다. 커밋 메시지를 입력하고 Commit changes를 누르면 삭제가 완료돼요.
💡 세 가지 모두 마지막엔 "커밋 메시지 입력 → Commit changes" 흐름이 똑같이 반복돼요. GitHub Pages나 Streamlit Cloud로 배포해둔 상태라면, 이렇게 파일을 바꾸거나 지운 뒤 몇 분 안에 자동으로 재배포에 반영됩니다.
2부 · Streamlit Community Cloud에서 배포하기

1부에서 GitHub에 올린 저장소를 Streamlit과 연결해 실제 웹 주소를 발급받는 단계입니다.

1

share.streamlit.io 가입

share.streamlit.io에 접속해 "Continue with GitHub"로 로그인하고, 저장소 접근 권한을 허용합니다.

2

"Create app" → 저장소 정보 입력

우측 상단 Create app 버튼을 누르고 "Yup, I have an app"을 선택한 뒤, 1부에서 만든 Repository / Branch(main) / Main file path(app.py)를 입력합니다.

3

Deploy 클릭 → 완료!

몇 분 뒤 내앱이름.streamlit.app 형태의 주소가 생성됩니다. 이 링크를 동아리 친구들에게 공유해보세요. GitHub에 새로운 커밋을 올릴 때마다(웹 업로드든 git push든) 자동으로 재배포됩니다.

⚠️ 무료 플랜은 앱이 오래 사용되지 않으면 잠들 수 있어요(첫 접속 시 몇 초 정도 깨어나는 시간이 걸립니다). 또한 공개 저장소의 코드는 누구나 볼 수 있으니, 비밀번호나 API 키는 코드에 직접 적지 말고 Streamlit의 secrets.toml 기능을 사용하세요.
10

보너스: 순수 HTML 페이지는 GitHub Pages로

지금까지는 파이썬 서버가 필요한 Streamlit 앱을 배포했어요. 그런데 만약 저장소에 있는 게 서버가 필요 없는 순수 HTML/CSS/JS 파일이라면(예: 오늘 이 수업 자료 같은 페이지), GitHub Pages라는 더 간단한 방법으로 배포할 수 있습니다. 클릭 몇 번이면 끝나요.

💡 Streamlit Cloud vs GitHub Pages — Streamlit 앱은 매번 파이썬 코드를 실행해줄 서버가 필요해서 Community Cloud에 배포합니다. 반면 순수 HTML 파일은 실행할 코드 없이 파일을 그대로 "보여주기만" 하면 되기 때문에, 서버 없이 정적 파일을 호스팅해주는 GitHub Pages로 충분해요.
1

파일 이름을 index.html로

저장소에 올릴 HTML 파일의 이름이 정확히 index.html인지 확인하세요. 이 이름이어야 주소를 열었을 때 자동으로 이 파일이 보입니다. (다른 이름이면 주소/파일명.html처럼 경로를 직접 붙여야 열려요.)

2

저장소 Settings → Pages

HTML 파일이 올라간 저장소 페이지에서 Settings 탭을 클릭하고, 왼쪽 사이드바의 "Code and automation" 항목에서 Pages를 클릭합니다.

3

Source 설정하기

"Build and deployment" 아래 Source 드롭다운에서 Deploy from a branch를 선택합니다.

4

브랜치와 폴더 선택 → Save

Branch 드롭다운에서 배포할 브랜치(보통 main)를 고르고, 폴더는 /(root)를 선택한 뒤(index.html이 docs 폴더 안에 있다면 /docs) Save를 누릅니다.

5

1~2분 뒤 주소 확인!

같은 Pages 설정 화면 위쪽에 https://아이디.github.io/저장소이름/ 형태의 링크가 나타납니다. 이후 저장소에 새 커밋을 올릴 때마다(웹 업로드든 git push든) 몇 분 안에 자동으로 재배포돼요.

💡 저장소가 Public이면 무료 계정에서도 바로 사용할 수 있어요.
